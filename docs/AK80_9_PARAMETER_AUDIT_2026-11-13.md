# AK80-9 V3 motor parameter audit

13 November 2026. The hardware gait scripts select `AK80-9-V3-servo` for the recorded trials. The local CubeMars AK Series Module Product Manual V3.0.1 (`../OSL Papers/1734428582786471.pdf`, p. 39) identifies the AK80-9 as KV100 and lists MIT command ranges of ±65 rad/s and ±18 N·m. These are protocol bounds for that manual's mode and revision. The model-specific [CubeMars AK80-9 V3.0 KV100 specification](https://www.cubemars.com/product/ak80-9-v3-0-robotic-actuator.html) lists 9:1, 0.095 N·m/A, 48 V, 9 N·m rated and 22 N·m peak output torque, and 12 A rated and 28 A peak as labelled ADC. Those catalogue entries and the manual's MIT bounds describe different quantities. The archived 60 A simulation clip is a separate software setting.

The screenshot describes the paper's drivetrain. The archived assembled implementation in `oslbench/sim/assembled_tracking.py` uses the paper's dynamics with the CAD belt ratio and scales the clipped simulation current by 0.5701/0.9972 before it enters the drivetrain. Both generated torque and current-dependent friction consume that scaled input. Dividing archived generated actuator torque by simulated applied current gives 0.5701 N·m/A across all 43,446 nonzero-current physics rows of the slow-walk case (`build/assembled_normal_20261104_C/simulation.csv`). The archived 5° ankle replay metadata states 0.5701 directly, and the archived 5° knee replay selects the same value through `kt: script`. Other experiment paths may use different choices.

The hardware gait code uses 0.5701 for logged torque estimates. Its angle PID commands current. Correcting the torque conversion changes estimates computed from those commands. The recorded hardware encoder angles are still the recorded angles. Current commands alone give no measured motor current or shaft torque.

Holding the 50/11 belt and current command fixed, the nominal manufacturer-based torque coefficient increases generated torque by 49.97% relative to the archived replay. At 10 A this is 5.701 → 8.550 N·m at the gearbox output before losses. The ideal rigid-equivalent joint slope changes from 2.5914 to 3.8864 N·m/A. Relative to the paper's rotor fit, 0.095 is 14.26% lower. The direction of change therefore depends on which baseline is used. The 0.5701 number is close to 6 × 0.095, but this arithmetic does not establish its provenance.

Tracking RMS, transient timing, peak current and belt deflection require replay because the PID responds to the changed plant. For a one-factor sensitivity experiment, first reproduce the archived baseline. Then use 0.855 N·m/A with identical gains, current convention, saturation, timing, initial conditions, load and belt settings. Keep the original effective current-dependent friction coefficient fixed if isolating the generated-torque term. A second case can use the existing rescaling path, which moves the effective friction coefficient to 0.07039 N·m/A. Label both as sensitivities until the controller current convention and as-built actuator torque per amp are verified. The current audit checked archived evidence and arithmetic. Dynamic results are pending the replay.
